## Hypothesis

Biasing the Mac-native Whisper path with a **domain vocabulary** (Lakeside street names, hard person names, service display names, service-area zips) via Whisper `initial_prompt` (already wired as ASR `hotwords`) will raise **NAME** and **ADDRESS** entity accuracy on telephony-ish slices (C1–C3) without regressing clean-audio (C0) WER beyond the declared margin.

## Metric

| Metric | Definition | Slice |
|--------|------------|-------|
| Primary | Mean entity accuracy for `NAME` + `ADDRESS` (`callscope.eval.scorers.entities`) | items with those refs; C1–C3 when condition present |
| Guardrail | Word Error Rate (jiwer) | C0 / `condition=C0` (or clean stand-in) |

## Minimum effect of interest

- **NAME+ADDRESS entity accuracy:** +5 absolute points on the biased (treatment) vs unbiased (control) paired set.
- **C0 WER guardrail:** treatment WER − control WER ≤ **0.005** absolute (0.5 points).

## Success criterion (decide adopt / reject)

**Adopt** hotwords into the default `local-mac-dev` worker/ASR config if:

1. Primary delta ≥ +5 points with paired-bootstrap 95% CI lower bound > 0, **and**
2. C0 WER delta ≤ 0.005 (point estimate; CI may be wide on small n).

Otherwise **reject** (keep hotwords optional / empty default) and log the null/negative result.

## Data discipline (no test leakage)

Hotword list is built **only** from:

- Scenario population pools in `callscope.eval.scenarios` (`_HARD_NAMES`, `_STREETS`) — template sources, not expanded test transcripts
- Business seed catalogues (`SERVICE_TYPES` display names, `SERVICE_ZIPS`)

Never from frozen-test or recorded-test transcripts.
