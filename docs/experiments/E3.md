# Experiment E3 — Endpointing / VAD tuning

**Task:** T-M5-03
**Status:** complete — **adopt** (see Results)
**Date:** 2026-09-22
**Choice rationale:** Review seed-demo root causes are tied between ASR (`RC-ASR-*`) and
turn-taking (`RC-TURN-*`). E1 already adopted domain hotwords for entity ASR. Next protected
experiment is therefore **E3** (endpointing/VAD). Optional E2 LoRA remains T-M5-05 / RAM-gated.

## Hypothesis

A small grid over `endpoint_min_delay_s`, `endpoint_max_delay_s`, `vad_threshold`, and
`barge_in_min_duration_ms` can reduce **premature** and **late** endpoint rates on caller-sim
oracle metrics without raising p50 response latency by more than **100 ms**.

## Metrics

| Metric | Definition | Direction |
|--------|------------|-----------|
| Primary | Mean of `sim.premature_endpoint` + `sim.late_endpoint` fail rates (oracle) | lower better |
| Guardrail | p50 intended response delay from knobs (ms) | treatment − control ≤ 100 ms |

## Minimum effect of interest

- Primary composite endpoint-error rate: **−5 absolute points** vs default WorkerConfig.
- Latency guardrail: p50 delta ≤ **100 ms**.

## Success criterion

**Adopt** the winning grid point into default `WorkerConfig` if primary Δ ≤ −5pp with paired
bootstrap CI upper bound < 0, and p50 latency Δ ≤ 100 ms. Otherwise **reject** (keep defaults)
and document the null/negative result.

## Data discipline

- Tune on **dev** stand-in (caller-sim scenarios, odd variant indices).
- Evaluate **once** on frozen stand-in (even variant indices / full scenario set).
- No LoRA / no weight downloads.

## Protocol

1. Lock this file (done before code).
2. Grid search on dev; pick by primary metric subject to latency guardrail.
3. One eval on frozen stand-in; paired bootstrap vs pre-E3 defaults; MLflow.
4. Decision in Results + `docs/DECISIONS.md`.
